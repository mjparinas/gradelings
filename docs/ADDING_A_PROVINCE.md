# Adding a province or state

Everything that differs by jurisdiction lives in its own folder, `src/content/<name>/`, described by a manifest (`manifest.ts`) and listed with one import and one line in `src/content/registry.ts` (both lists alphabetical, so parallel state PRs rarely collide). No screen changes are needed.

1. **Framework.** Create `src/content/<name>/framework.ts` exporting a `Framework` (the type is in `src/content/frameworks.ts`): id, slug, `curriculumName`, grades, subjects offered, report-card scale and guide, and the scoring scheme.
2. **Official standards.** Everything the research used goes in `docs/research/<name>/`, committed, so it can be checked again after the website changes or the document is taken down:
   - `source/`: the official documents as downloaded (PDF, HTML, spreadsheet or JSON), plus a `pdftotext -layout` `.txt` beside each PDF, so a diff shows what changed in a new edition. Commit them even when the site allows automated downloads. If a site blocks downloads, ask the owner for the files and commit those. Keep each file under 50 MB; for a bigger document, commit the parts the research reads and say so in the README.
   - `fetch.sh`: downloads every file in `source/` again from its official URL (default folder `source/`), with a comment naming each document and its edition.
   - `build_outcomes.py` (run with `python3 -I`): turns `source/` into `outcomes.json`, the codes and text the framework's `contract.ts` checks citations against. Running it on the committed `source/` must reproduce the committed `outcomes.json` exactly. Don't edit `outcomes.json` by hand; fix the script.
   - `README.md`, like `docs/research/washington/README.md`: each source with its URL, edition and download date, how to rebuild, how citations are checked, and known gaps.
3. **Courses.** For each grade add `src/content/<name>/g<N>.ts` exporting `courses`. A course lists:
   - `units`: units written for this jurisdiction. Give them ids that do not clash with BC ids.
   - `shares`: BC (or other) unit ids to reuse. A framework can also share another framework's own units (Alberta shares some Ontario units); list that dependency in `depends` in its manifest so the other framework's file is downloaded too. Each gives the new standards text for that unit. Share only after sampling the unit's questions and confirming they fit the new curriculum.
   - `order`: the unit order for this framework.
   - `bigIdeas`: strand headings.
4. **Manifest and registry.** Create `src/content/<name>/manifest.ts` with `defineFramework({ id, framework, grades, guides, french })`: a dynamic `import()` for each grade file (each grade and framework is its own download), the guide copy, and the grades it teaches each French subject in (`gradeRange("4", "9")`, or `[]`). Set `upcoming: true` while it is built. Then add the manifest to `REGISTRY` in `src/content/registry.ts`, in the place the pickers should list it. That one line gives it a `FrameworkId`, puts it in `FRAMEWORKS` (the province pickers in Children, Settings and the Start screen, public pages, the sitemap, classroom mode and `/for-teachers/`), the apps' grade loaders, `all.ts`, the guide pages and the content tests.
5. **Contract.** Create `src/content/<name>/contract.ts` (`FrameworkContract` in `src/content/contract.ts`): `cite` checks a unit's citation against the official data in `docs/research/<name>/`, `ownPrefix` and `ownSharedWith` say which units are its own and who else may use them, `foreign` lists the places a borrowed unit must not name, and `plan` is its plan if it has one. `contract.test.ts` then runs every framework check on it; a test file in its folder is only for rules that are its alone.
6. **Parent and public pages.** A new region gets the same parent content as every other region, in the same change (see "Region parity" in AGENTS.md). Curriculum pages, the report-card page and the sitemap come from the framework automatically; the rest needs writing or checking:
   - **Parent guides** (the site's SEO content for parents): a `FrameworkGuides` in `src/content/<name>/guides.ts`, named by `guides` in the manifest, with grade notes for every grade, the region's competencies or learning-skills page, its assessment page (provincial or state tests), and a French guide when it teaches French. Help pages and worksheets per grade and subject follow from the courses. The competencies and assessment pages are served at the slugs the guide copy names (`competencies.slug`, `assessment.slug`) with no route folder of their own; a slug must not be a grade slug.
   - **Report card:** the framework's `reportCard` guide feeds `/report-cards/{slug}/` and the parent area, so make it say what that region's report card says.
   - **Teachers:** `/for-teachers/` pages and classroom mode follow from the registry; check the pages read well.
   - **Share cards:** check the guide and unit cards for the region read well (`ogText.ts`).
   - **Site-wide copy:** search for every hand-written list of regions, scales or prices and add the new one: help FAQs (`src/app/help/faqs.ts`), comparison pages (`src/content/compare.ts`), home and pricing pages, metadata, manifest and terms. Prefer reading names from `FRAMEWORKS` (`regionList`, `listRegions`).
   - **A new country** also needs its currency and prices (`plan.ts`), a spelling and number layer (`src/content/locale.ts`), grade wording (`gradeLabel`), its privacy and consent rules on `/privacy/` and in `docs/school/`, and comparison-page facts for its families (prices in its currency, its app store).
   - **School privacy:** a `schools.ts` in the folder (`SCHOOLS`, wired as `schools` in the manifest) is the paragraph `/privacy/` shows for the region's schools; add the matching bullet to `docs/frameworks/<slug>.md` under Schools.
   - **Contract:** in the new `contract.ts`, `adoptsFrom` lists the frameworks whose own units it borrows. No other framework's contract changes.
   - **Decisions and known gaps** go in `docs/frameworks/<slug>.md` (copy `docs/frameworks/us-state-template.md`), not in AGENTS.md.
   - **Lessons** for its own units are attached inside its folder with `withLessons`, not appended to the shared `src/content/lessons/` files.
   - Anything not done goes in the PR description and in the framework's Known gaps.
7. **Lock it.** Run `npm run curriculum:lock` to write `src/content/locks/<id>.json` and record its download sizes. It writes `locks/<id>.json`, `locks/dates/<id>.json` and `locks/sizes/<id>.json`. Only the new framework's three files should change; if another framework's lock changes, the new content reached into it.
8. **Run** `npm test`, `npm run lint`, `npx tsc --noEmit`, `npm run build`, and the e2e scripts in AGENTS.md.

Progress is shared across frameworks for shared unit ids, so a child who switches province keeps the progress they earned on units both provinces teach.
