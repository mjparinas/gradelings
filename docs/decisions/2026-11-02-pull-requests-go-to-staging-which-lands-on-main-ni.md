# Pull requests go to `staging`, which lands on `main` nightly

**Pull requests go to `staging`, which lands on `main` nightly** (November 2, 2026): every agent and person opens pull requests against `staging`, not `main`. `.github/workflows/promote-staging.yml` merges `staging` into `main` each night (09:00 UTC) when CI passed on staging's latest commit, then merges `main` back, so Vercel makes one production build a day instead of one per merge (build minutes were most of the Vercel bill). Run the workflow by hand to ship sooner; a real hotfix may still go to `main`. CI runs on pushes to both branches. `main` only accepts pull requests, so the workflow opens one from `staging` and merges it (it needs "Allow GitHub Actions to create and approve pull requests" turned on; setup is in the workflow's header). Scheduled workflows run from the default branch, so `main` stays the default.
