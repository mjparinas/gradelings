# Gradelings: guide for agents

Gradelings is curriculum-matched practice, learning games and parent reports for Kindergarten to Grade 9. It launches with the BC Curriculum and is built to add other provinces and US states. This file records the product and design decisions already made, and why. Follow them. If a task seems to need one changed, raise it with the owner first; don't quietly work around it.

## Commands

```bash
npm run dev                 # http://localhost:3000
npm test                    # content checks for every unit + logic tests + province parity checks (~20 s)
npm run curriculum:lock     # re-record src/content/locks/ after an intended content change (see Content rules)
npm run test:mutation       # Stryker on the scoring/rules files in src/lib (~9 min from scratch, seconds when incremental); report in reports/mutation/
npm run test:mutation:server  # Stryker on sync, billing webhook, auth, consent, codes, students and admin (~1 h from scratch); report in reports/mutation-server/
npm run lint
npx tsc --noEmit            # run `npx next typegen` first in a fresh checkout (PageProps/LayoutProps)
npm run build && npm start  # offline/service worker only works in a production build
node scripts/e2e.mjs http://localhost:3000 e2e-shots --offline   # full playthrough + sync
node scripts/e2e-devices.mjs http://localhost:3000                # layout on 14 phones/tablets
node scripts/e2e-offline.mjs                                      # real offline (starts its own server), plus maintenance mode on a saved device
node scripts/e2e-classroom.mjs http://localhost:3000              # teacher adds a student, who signs in with codes, opens a lesson and practises
node scripts/e2e-a11y.mjs http://localhost:3000                   # axe-core WCAG 2.2 A/AA, plus colour-blind checks (screenshots in e2e-shots/a11y)
node scripts/e2e-keyboard.mjs http://localhost:3000               # keyboard-only run-through (skip link, focus rings, a session by keys, parent PIN and tabs) and Windows high contrast
node scripts/e2e-admin.mjs http://localhost:3000                  # admin panel (server needs ADMIN_EMAILS=admin-e2e@example.com): to-do list, funnel, traffic, emails, inbox, automations, flags, codes, A/B tests, users and billing, CSV, system, maintenance mode, axe scan
node scripts/ios-screenshots.mjs http://localhost:3000            # App Store screenshots, iPhone 6.9" and iPad 13" (docs/IOS.md)
node scripts/bench-clicks.mjs http://localhost:3000 3              # tap-to-feedback and tap-to-screen times on a slowed tablet with a year of practice (CHROMIUM_PATH for another browser)
```

Before you push, run tests, lint and typecheck. For UI or flow changes, also run the e2e scripts.

Whenever you add a new feature, write a test for it in the same change. When extending an existing feature, add or update tests for the behavior you changed.

- **Playwright** is a dev dependency, pinned. Install the browsers once with `npx playwright install chromium webkit` (on Linux add `npx playwright install-deps`).
- **CI** (`.github/workflows/ci.yml`) runs types, lint and the audit (one machine), unit tests (three machines, dealt out by `scripts/test-shard.mjs` using the weights in `scripts/test-weights.json`; add a heavy new test file there) and the build in parallel, then the browser tests on five machines (device layouts in two shards, and three machines that each run a few e2e scripts one after another with `scripts/ci-each.mjs`). Require the "CI passed" job in branch protection.
  - **Docs-only pull requests skip the heavy jobs:** a `What changed` job lists the pull request's files, and when they are all under `docs/` (except research JSON), `ios/`, `android/` or `*.md`, the types, unit, build and browser jobs are skipped ("CI passed" still reports). Pushes to main always run everything. `.github/workflows/cache-cleanup.yml` deletes a closed pull request's caches and, weekly, pull request caches older than 3 days.
  - **Content tests share workers:** `vitest.config.mts` has two projects. Tests under `src/content/` run with `isolate: false` (about 40% faster; one worker per file cost most of the time), so they must not use `vi.mock`, stub globals or change module state; everything else keeps one worker per file. `scripts/test-shard.mjs` strips the `[project]` prefix `vitest list` prints.
  - **Keep the job count low:** every open pull request shares the account's limit on machines running at once, so a new quick check goes into an existing job (or an existing browser group) rather than a job of its own.
  - **Caches:** the 2 GB Next build cache is saved only on main (pull requests reuse it), so it never pushes the node_modules and browser caches out of the repository's 10 GB; those are saved as soon as they are made. The build is shipped to the browser jobs as one zstd tar (`scripts/ci-unpack.sh`), without the voices, which come from the cache.
- **iOS** (`.github/workflows/ios.yml`): when `ios/` changes, a Mac runner builds the app and runs its Swift tests on an iPhone and an iPad simulator. Run it by hand to sign and upload to TestFlight (secrets in `docs/IOS.md`). There is no Mac here, so this workflow is the only Swift compiler check.
- **Stale styles:** if a change to `globals.css` (`@theme`, `@custom-variant`) doesn't show up in a build, delete `.next` and rebuild.

### What the e2e scripts cover
Tests are duplicated across screen sizes only where layout can break:

- **`e2e-devices.mjs`, on every device:** the cheap layout checks.
  - The 14 devices:
    - Galaxy S9+, Galaxy S24 and Pixel 7;
    - iPhone SE, iPhone 15 and iPhone 15 Pro Max;
    - iPhone 15 and Pixel 7 in landscape;
    - iPad Mini and iPad Pro 11, portrait and landscape;
    - Galaxy Tab S4, portrait and landscape;
    - a 1366×768 Chromebook.
  - The checks:
    - no sideways scroll;
    - the main button above the fold;
    - touch targets at least 48 px for kids and 44 px elsewhere;
    - the feedback bar's button fully on screen;
    - parent reports not overflowing.
- **`e2e-devices.mjs`, one device per class** (smallest phone, phone landscape, tablet portrait, tablet landscape): the riskier flows.
  - Kindergarten sizing.
  - An arcade game's play area fitting the screen.
  - Toasts not blocking taps.
- **`e2e.mjs`:** the full playthrough on an iPad-sized screen plus a phone. It covers every mode and game, the parent area, sign-up, two-device sync, and offline progress uploading on reconnect. CI runs it as three parts, `--part modes`, `--part parents` and `--part sync --offline`; with no `--part` it runs everything.
- **`e2e-classroom.mjs`:** a teacher (made through the API, email confirmed straight in the database file) adds a student; the student signs in with codes, sees the assignment, opens a lesson, practises and signs out; the teacher sees the results.
- **`e2e-keyboard.mjs`:** a keyboard-only run-through on a 1366×768 Chromebook. Every screen is walked with Tab (each stop needs a focus ring and must not be hidden under a sticky header or the feedback bar); the skip link, a whole Adventure session and a money practice unit (number keys, the keypad, Enter, Tab), the parent PIN and every parent tab are driven with keys alone. Then it turns on forced colours (Windows high contrast) and checks switches, sliders, progress bars and right answers still show. Run it against a production build: the `next dev` overlay traps Tab.
- **`e2e-offline.mjs`:** stops the server so only the service worker can answer. Playwright's `setOffline()` doesn't cut off service worker requests, so it can't prove the cache works.
- **WebKit:** iPhone and iPad profiles run in WebKit when it's installed, otherwise in Chromium at the same size, pixel ratio and touch settings.

## Product decisions

### Positioning
- **Audience:** parents of children in Kindergarten to Grade 9. Kids use the app; parents choose it, configure it and pay.
- **We differentiate on clarity, kindness and usability, not price.** IXL is expensive and hard to use, and Khan Academy is free. We win by:
  - speaking the language of the report card;
  - giving kind, encouraging feedback;
  - making it as compelling as a good video game.
  - Research is in the separate [gradelings-research](https://github.com/mjparinas/gradelings-research) repository (paths written `gradelings-research/...`).
- **Name:** "Gradelings" is a working name. It is set once in `src/lib/brand.ts`; never hard-code it elsewhere. The name was chosen because it works across provinces and countries.
- **Platform:** a web-first installable app (PWA) built with Next.js. Android is a Trusted Web Activity that wraps `/play/` (`android/`, `docs/ANDROID.md`), not Capacitor. iPhone and iPad share one universal app, a small native Swift shell around `WKWebView` (`ios/`, `docs/IOS.md`), also not Capacitor: it adds offline (app-bound domain), haptics, the share sheet, printing and downloads, and opens only `/play/`, `/parents/`, `/account/` and `/shared/` in the app. Don't add features that only work in a native shell.
- **Store apps sell nothing:** inside the Android and iOS apps (`isStoreApp` in `src/lib/twa.ts`) there are no prices, payment buttons, subscribe prompts or mention of where to pay, and the iOS app has no redeem-code box (`isIosApp`). In-App Purchase isn't built (owner's decision, `docs/IOS.md`).

### Money
- **No ads, ever. Never sell data.** Kids can never buy anything; coins are earned only by learning. The one exception is testing: a device signed in to an admin account shows unlimited coins (`TEST_COINS`, `docs/ADMIN.md`), never stored or synced.
- **Family plan:** C$14.99/month or C$119.99/year, with "Save 33%" on the yearly plan, for up to 5 children.
  - The plan includes a 30-day free trial with everything on and no card needed.
  - Subscribing during the trial keeps the days left: checkout saves the card and starts a Stripe trial that ends with ours (`firstChargeAt` in `plan.ts`), unless fewer than 49 hours are left or the family had a paid plan before.
  - A device with no account gets a quiet "For grown-ups" card at the end of a lesson (after the first lesson, then daily in the trial's last week; `src/lib/saveNudge.ts`, `SaveProgress.tsx`, flag `save-progress-card`), because trial emails need an account. It asks for an email only (owner, October 2026): "Send me the reports" makes an account with no password (`passwordless` on `/api/auth/signup/`, `password_hash = '!'`, like a Google-only account) and the weekly report on, signs the device in and sends the confirmation email; the weekly report goes only once the email is confirmed. There is no grown-ups screen before the first question any more (the `email-at-start` step was removed).
  - Public pages' "Try it free" and "Play free" buttons open the app on what the page is about (`playHref` in `src/lib/playLink.ts`, passed as `play` to `SitePage` and `SubscribeActions`): the hello screen is skipped (unless a parent has signed in on the device before), the province or state and grade show as one line with "Change", so the name is all a new child types, and a link that names a unit starts that unit's practice at once (little kids see its lesson first).
  - Pages people find from a search (curriculum, guides, worksheets, report-card pages) lead with the free trial (`lead="trial"` on `SitePage` and `SubscribeActions`): Play free first and green, and no full-width Subscribe bar on phones. Home, pricing, about and the parent area keep Subscribe first (owner, October 2026; cold search visitors clicked the trial about six times as often). A unit page's tap-to-answer sample questions can be answered on the page (`TryChoices`), with the app link after the answer.
  - After the trial, the first 2 units of every course stay free forever.
    - "First 2" counts in the child's own curriculum (`unitIndexIn` in `src/content/index.ts`, used by `useAllowed` and `src/lib/paywall.ts`): a ref's `course` is every framework's units merged and a US child's units are localized copies, so never count with `ref.course.units.indexOf(ref.unit)` (before November 2026 that opened every unit to free US families and fewer than 2 in Ontario and Alberta).
  - **Full parent reports are for members** (owner, November 2026; flag `members-reports`): on the free plan, Reports keep the summary (totals, strengths, worth practising, math facts, reading level, trophies, milestones, 7 and 14 days); the charts, the every-unit table, "Is it working?", 30 and 90 days, printing, share links, the report-card conversation sheet and Year in review show a `MembersOnly` card with the child's own numbers instead (`src/components/parents/MembersOnly.tsx`; no payment named in the store apps). The placement test, the report card guide and the weekly email stay free.
  - **The paywall names what a family would lose** (flag `personal-paywall`, `src/lib/paywall.ts`): the upgrade banner, the Subscription page and the trial emails list each child's started units that the free plan keeps closed ("Maya has started 9 units. 6 of them lock when the trial ends: Fractions, Place value and 4 more."); a child with nothing to lose gets no line.
  - All of this lives in `src/lib/plan.ts`; read the numbers from there.
- **Refunds** (owner, October 2026): any payment, renewals included, is refunded in full when the parent asks within 14 days (`REFUND_DAYS` in `plan.ts`), no reason needed; the plan then ends. The owner refunds and cancels from the admin panel. No renewal reminder emails (owner's decision).
- **Support promise:** a person replies within one business day (`REPLY_TIME` in `src/lib/brand.ts`, shown on Contact, Help, the contact form and `/status/`). Keep it true.
- **US families** (owner, October 2026): US$14.99/month or US$119.99/year ("Save 33%"), one site for both countries. `PRICES` is the Canadian price list; `pricesFor(country)` gives a family's own (`PRICES_BY_CURRENCY`). US labels say "US$". A family's `country` (`families.country`, default `CA`) is set on the server from the first child added: US when that child follows a US curriculum (`familyCountry` in `src/lib/coppa.ts`), and it can change only while the server holds none of the family's children. No country picker.
  - Public pages show US prices because a US framework is in `FRAMEWORKS` (`offersUsd` in `src/components/site/provinces.ts`): the pricing page has a CAD/USD switch (Canadian first), and the home page, pricing metadata, help FAQs and the app's JSON-LD (`siteCurrencies`) list both. The old `us-launch` flag is gone.
  - **COPPA consent:** a US family's children and progress don't sync until a parent ticks the notice in the Parent area (`UsConsent.tsx`, text in `CONSENT_NOTICE`). Consent ("email plus") is stored on the family (`consent_at`, `consent_version`, `consent_method`); a confirmation email goes at once and a second one from the daily job a day or more later, each with a withdraw link (`/account/consent/`). Withdrawing deletes the children's server data (`deleteChildData`) and stops their upload. A paid checkout also records consent (webhook), but nothing depends on it. Class student accounts are covered by their school and never asked. Canadian families never see any of this.
- **Payments:** Stripe Checkout and the Billing Portal, called over raw HTTPS with no SDK (`src/server/stripe.ts`).
  - Until Stripe keys are set, billing runs in a simulated dev mode (`ALLOW_DEV_BILLING=1` turns it on in production for staging).
  - US checkout uses `STRIPE_PRICE_MONTHLY_USD`/`STRIPE_PRICE_YEARLY_USD` (unavailable with a clear message without them) and Stripe Tax (`automatic_tax`, billing address); Canadian checkout is unchanged. Referral credits go in the family's currency; discount codes are percentages, so they work in both. The admin dashboard never adds USD to CAD: US money has its own tile (`revenue.usd`).
- **Sales and the founding-family code:** the owner runs site-wide sales from the admin panel's Sales tab (presets such as Black Friday or Back to school, linked to an existing code; `src/lib/promo.ts`). A banner with the code and a countdown shows above the header on public pages and on Subscription, never in the store apps. `FOUNDER` (33% off every payment) is seeded in `src/server/db.ts`. Pricing copy leads with the cost per child (`perChildMonthly` in `plan.ts`, always "with 3 children").
- **Redeem codes** (`src/server/codes.ts`, `docs/CODES.md`): the owner makes codes in the admin panel (or through `/api/admin/codes/` with `ADMIN_TOKEN` from scripts) and a signed-in parent enters one under Subscription > "Have a code?".
  - An access code gives free access for a number of days, or for life (`families.access_until`; lifetime is `LIFETIME_ACCESS` in `plan.ts`). It stacks on access already granted and is kept apart from `plan`, so a Stripe webhook never undoes it.
  - A discount code saves a percentage off for the next checkout (`families.discount_code`), sent to Stripe as a coupon made on first use; the paid checkout clears it.
  - Each family can use a code once; codes can have a use limit and an expiry date. Wrong, disabled, expired and used-up codes all get the same answer. Class student accounts can't redeem.

### Not tied to BC: every framework, every grade
- **Everything that differs by province or state lives in a `Framework`** (the type is in `src/content/frameworks.ts`; each framework's object is its folder's `framework.ts`): grades, report-card scale, report-card guide and slug.
  - **The registry** (`src/content/registry.ts`) lists every framework's manifest (`<folder>/manifest.ts`, `defineFramework`): its `Framework`, a loader per grade file, its guides, the grades it teaches each French subject in, `depends` and `upcoming`. `FrameworkId`, `FRAMEWORKS`, the apps' loaders, `all.ts`, `GUIDES` and the teacher pages are all read from it, so a new framework is its folder plus one registry line.
  - **Contract tests** (`src/content/contract.test.ts`) run the same checks on every framework in the registry: citations are real standards for the unit's grade and subject, own units go only where allowed, borrowed units name no other region, the plan places each unit once and shares only BC units, and every US state is in US English on the plain practice scale, with units free of Canada and Canadian money, of other states' places (`otherStates`) and of other states' Tribal units (`tribal`). What differs per framework is in its folder's `contract.ts` (`cite`, `ownPrefix`, `adoptsFrom`, `foreign`, `otherStates`, `tribal`, `plan`). Each unit's questions are generated once for the whole file and reused by every framework that checks it. A framework's own test file keeps only the rules that are its alone (its own unit list, its grade themes); don't copy the shared checks into it. Likewise `src/components/site/guides.test.ts` checks every US state's parent guides (pages built, notes for every grade, US spelling), so a state's `src/app/guides/[framework]/<slug>-guides.test.ts` keeps only its tests, competencies and the other states it must not name.
  - Each unit carries `standards[frameworkId]`. Each course carries `bigIdeas[frameworkId]`.
- **No BC-specific wording in UI code.** Read names from the framework, such as `curriculumName` and the level labels.
  - Public URLs are `/curriculum/{framework-slug}/{grade-slug}/{subject}/{unit}/`, `/guides/{framework-slug}/...` and `/report-cards/{framework-slug}/`.
- **Adding a province or state** means adding a `Framework` and its standards, not new screens (`docs/ADDING_A_PROVINCE.md`). BC content follows the BC curriculum; Ontario follows the Ontario curriculum; Alberta follows the Alberta curriculum; any other province or state follows its own official curriculum, with its own spelling rules (Canadian spelling in every Canadian province).
- **Frameworks:** the registry (`src/content/registry.ts`) is the list of every province and state, with each one's id, slug and French grades in its folder's `manifest.ts`; read it, don't copy it into prose, tests or comments (tests and copy work out counts and names from `FRAMEWORKS`). BC, Ontario and Alberta cover Kindergarten to Grade 9 in math, language, science, social studies and the two French subjects. A parent picks the province or state per child (when adding the child, in Children and in Settings). Progress is shared between provinces for shared unit ids.
- **Whenever you create or change content, apply it to every framework.** If you add a unit, grade, subject, guide, trophy, quest or page for one province, add the matching one for every other province and state in the same change, or say plainly in the PR which framework is still missing and why. If you change how a grade works (its units, French, scoring, wording), check that grade in every framework, because grade changes apply across regions. `src/content/coverage.test.ts` fails when a framework is missing a grade, a core subject, Big Ideas or French in a grade its manifest says it teaches.
- **All sales, call-to-action and marketing copy says "Kindergarten to Grade 9"** and names the provinces and states it covers. Prefer reading the grade range and region names from `FRAMEWORKS` over typing them (`regionList`, `regionSummary`, `regionWord` and `byCountry` in `src/components/site/provinces.ts`; `gradeSpan` and `gradeLabel` in `src/components/site/curriculum.ts`).
  - **US version:** one site serves both countries, so site-wide copy keeps "Kindergarten to Grade 9" and says "province or state" once a state is offered. A page about one US state (its curriculum, guides, report card, teacher pages and share cards) is in US English: "kindergarten through 9th grade", "4th grade", "practice" as a verb, "color". Read grade names with `gradeLabel(framework, grade)`, never `GRADE_LABEL`, on framework pages, and pass hard-coded page copy that has Canadian spelling through `say(framework, text)`. Canadian pages and copy stay as they are. Pickers group Canadian provinces and territories, then US states (`byCountry`). When the range changes, search the repo for the old range (`README.md`, pricing, help FAQs, metadata, manifest, share image, guides, compare pages, terms, plan features) and update every hit.
- **Do not support Quebec for the time being.** No Quebec framework, curriculum, guides, report-card page, or marketing that offers Quebec as a choice. Questions that mention Quebec as a place in another province's content are fine. Raise it with the owner before adding Quebec support.

- **Per-framework decisions live in `docs/frameworks/<slug>.md`, one file per framework, not in this file.** Read the file for the province or state you are working on before changing its content; it records the standards source, grade placement, report card, content sources, the Indigenous content rules, parent guides, school privacy law and known gaps. Every framework's file has the same headings (Framework, Standards, Content, Report card, Parent guides, Schools, Known gaps), and `docs/frameworks/us-state-template.md` is the template for a new US state. Keep a framework's file true when its content changes.
- **Adding a state without conflicting with other open state pull requests:** a new state should touch almost only files that are its own.
  - Its own: `src/content/<folder>/`, `docs/research/<folder>/` (its JSON) and its folder in gradelings-research, `docs/frameworks/<slug>.md`, `src/content/locks/<id>.json`, `src/content/locks/dates/<id>.json`, `src/content/locks/sizes/<id>.json` and its own tests.
  - Its own lessons: attach them to the state's own units with `withLessons` inside the state's folder (`src/content/<folder>/lessons/`), so they ship in that state's grade download, not in the shared `src/content/lessons/<grade>-<subject>.ts` files that every state pull request would append to. Add to the shared files only for a lesson on a unit that already existed.
  - Its school privacy paragraph: `schools` in its manifest (`src/content/<folder>/schools.ts`), which `/privacy/` renders on its own.
  - The shared lines: one import and one entry in `src/content/registry.ts`, which keeps each list in alphabetical order by folder so two new states rarely touch neighbouring lines. If you resolve a conflict there, keep both states' lines.
  - Never write the number of states or a list of state names in code, tests, comments or docs outside the registry (no "nineteenth", "20 US states", "Oregon, California, ... and Virginia"). Tests derive counts and names from `FRAMEWORKS`; comments say "other US states".
  - After a change that moves other frameworks' locks, run `npm run curriculum:lock`; the lock files are one per framework, so a conflict in one is resolved by regenerating that file.

### Scoring follows the report card
- **BC uses the four-level Provincial Proficiency Scale:** Emerging, Developing, Proficient, Extending.
  - Parents see the official wording plus a plain-language "at home" note.
  - Kids see 🌱 Seedling, 🌿 Sprout, 🌳 Tree and ⭐ Star.
- **Unit level** (`src/lib/proficiency.ts`) is based on recent first-try accuracy:

  | Level | Requirement |
  | --- | --- |
  | Not started | No attempts |
  | Fewer than 4 attempts | Developing at ≥75%, otherwise Emerging |
  | **Proficient** | ≥75% and ≥8 attempts |
  | **Extending** | ≥90%, ≥16 attempts **and a passed Challenge** |
  | Developing | ≥50% |
  | Emerging | Otherwise |

- **Reports must say this reflects practice, not a report-card mark.** The teacher decides proficiency.
- **The report card explainer appears in two places:** the parent area and the public `/report-cards/{slug}/` page. Both use `ReportCardGuide`.

### French
- **Two opt-in subjects, off by default** (a parent turns them on per child in Settings > Subjects): `immersion` (Français langue seconde – immersion) and `core-french`.
  - **BC:** Immersion from Kindergarten to Grade 9; Core French from Grade 5 to Grade 9 (BC requires a second language from Grade 5).
  - **Ontario:** Immersion from Grade 1 to Grade 9; Core French from Grade 4 to Grade 9 (Ontario requires Core French from Grade 4).
  - The grades each province offers are fixed in `french` in its manifest (`src/content/<folder>/manifest.ts`), and `coverage.test.ts` checks the courses match. Adding a province means setting its French rule there.
- **Subjects are a registry** (`SUBJECTS` in `src/content/subjects.ts`): each subject's names, colours, mascot, the name parents search for (`seoTitle`) and, for a second language, its `language`. Core subjects are the ones without a language (`CORE_SUBJECTS`); code reads `subjectsIn("fr")` and `languagesOf(subjects)` instead of naming Immersion and Core French, so another language (Spanish, say) is its id in `SubjectId`, one entry there and its grades in each manifest.
- **They never count toward "every unit in your grade" goals or the Grade Champion trophy** (`isCoreSubject`), and reports only list French units once a child has started them.
- **Immersion prompts are in French and set `lang: "fr"`**, so read-aloud uses a French voice (`speak(text, uri, "fr")`). Hints stay in English for parents. Core French prompts are in English with French answers.
- **BC Big Ideas are copied word for word from the official BC PDFs** (Immersion: `en_fral_k-9_elab.pdf`; Core French: `en_languages_5-10_core-french.pdf`). Ontario French units cite the Ontario FSL curriculum.
- **French read-aloud** (`src/lib/readaloud.ts`) speaks each part of a question in its own language: Immersion prompts are French; Core French prompts are English with French marked in « » (`tagCoreFrench`), and `choicesLang`/`visualLang` mark French choices and stories. Parents pick a separate French voice under Account (`grademap.voice.fr`, per device). Hints are always read in the English voice.
- **French trophies** live in their own `FRENCH_TROPHIES` list in `src/lib/trophies.ts` (category "French"), plus a French mastery trophy per grade; French still doesn't count toward Grade Champion. French trophies and the two French practice ladders only show where the child's grade and curriculum teach that French (`applies`), so none appear in Ontario Kindergarten.
- **Parent guide:** each province has a French guide at `/guides/{framework-slug}/french/` that compares Core French and French Immersion for that province.
- **Verify French against the official sources:** curriculum.gov.bc.ca (`/curriculum/fral/{grade}/core` and `/curriculum/core-french/{grade}`) for BC, and the Ministry's FSL curriculum for Ontario.

### Spanish
- **One opt-in subject, `spanish`, off by default** (owner, October 2026): a parent turns it on per child in Settings > Subjects, like Core French. Grades 3 to 9 in every province and state, behind the flag `spanish` (off until the owner has tried it): while it's off the switch is hidden, teachers can't assign it, its trophies and quest don't show, and it has no public pages (`publicSubject` in `coursesFor`); a child who already has it on keeps it.

### Modes
- **Adventure** is the headline mode and needs no topic picking.
  - It keeps mixing subjects and units, weighted by weakness, novelty, spacing and recency (`src/lib/adaptive.ts`).
  - Difficulty adapts per unit, with a checkpoint every 10 questions.
- **Practice:** choose a subject and unit.
- **Review:** 10 questions from tricky spots only.
- **Speed Run:** 60 seconds (90 for little kids), quick-answer question types, flash feedback.
- **Daily Challenge:** 10 questions, seeded so everyone gets the same set that day.
- **Challenge:** 10 questions at difficulty 3, a 300 s time limit (420 s for little kids) and no retries.
  - Passing takes 8 out of 10, and passing is the only way to reach Extending.
- **Math Facts** (`src/lib/facts.ts`, `Facts.tsx`, `#/facts`; flag `math-facts`): addition and subtraction facts to 10 (Grades 1 and 2, 45 each) and to 20 (Grade 2 up, 100 each), then times tables and division facts to 10 × 10 (Grade 3 up, 100 each). None in Pre-K or Kindergarten (no typed answers). Rounds of 20 typed facts (10 with short sessions); a right answer moves straight on, a miss gets the usual hint and another try, and "Show me another way" opens the set's strategy lesson.
  - Each fact is tracked on its own: answer events carry `fact` ("mul:7:8") and `derive` builds `facts` from them, never stored. A fact is known after its last two tries were right the first time without a hint. Missed facts come back most, then facts being learned, then new ones (slower while 8 are being learned), then known ones now and then (`pickFact`). Fact sets share ids, so "3 + 4" practised in Adding to 10 counts in Addition facts too.
  - Fact answers use the unit key `<grade>/math/facts`, so they count as math practice (XP, minutes, subject totals, streaks) but never as a unit: no level, no report-card row, no "ask a grown-up" entry and no question report.
  - Older kids get a home-screen tile; little kids (Grade 1) find it on the Lessons screen. It needs the family plan (`Feature` "facts") and math switched on. Parent Reports say "knows 64 of 100 times-table facts" for each set practised, with the facts still being practised (`FactsLine`). Trophies: Fact Finder, Fact Collector (50 known) and one gold per set of 100 (`facts-add`, `facts-sub`, `facts-mul`, `facts-div`), shown only where the grade has the set; daily quest "Do a Math Facts round" for non-little kids.
  - **Facts chart** (`FactChart` in `Facts.tsx`, `#/facts/{set}`, `factGrid` in `src/lib/facts.ts`): the adding and times sets (`hasGrid`) open as a 10 × 10 chart from "See my chart" once a fact in the set has been tried. A known fact shows its answer, one being practised a dot, a new one nothing; each cell has its fact as its name, and forced colours give known and practised cells their own edges (`.fact-cell`). Taking away and dividing have no chart, since they don't read as one.

### A level for each subject
- **A parent can let a child practise one core subject at another grade** (`src/lib/subjectGrades.ts`, `ChildSettings.subjectGrades`, flag `subject-levels`), from the Placement test page: after a result, "Practise Grade 4 math" switches that subject only, with "Back to Grade 3 math" and a picker for any grade. French subjects can't be moved.
- Practice, Adventure, Review, Speed Run, the Daily Challenge, the home screen's cards, the focus-unit picker, stickers, the trail map and parent Reports read units through `practiceCourses`/`practiceUnitRefs` (`src/content/index.ts`), which take the set subject's course from its grade. Progress stays under that grade's unit keys, so switching back loses nothing. Reports tag units from another grade, and still list own-grade units already started.
- The extra grade downloads with the child's own (`practiceTargets`) but never blocks the app: until it is in, the subject stays on the child's grade. Grade-wide goals (Grade Champion, "every unit in your grade") stay on the child's own grade. When the child's grade changes, set subjects move by the same number of grades (`shiftSubjectGrades`). Kids never see a grade label for a subject.

### Reading-level matching (language arts)
- **Passages are tagged by computation, not by hand** (`src/lib/readingLevel.ts`): a passage or story in English gets a level on the grade scale from its text (Flesch-Kincaid, 0 to 12), so all existing language arts content is levelled and new passages are too. French and non-passage questions have none.
- **A child's level is estimated from answers**: Session logs `rl` (the passage's level) on language arts answer events; `derive` keeps the last 100 as `reading`; `estimateReadingLevel` moves a grade-scale ability up and down (about 3 in 4 right at the passage's own level). It needs 8 passage answers first. Nothing is stored; it is not a report-card mark.
- **What changes:** in Practice, Adventure and Review, a language arts unit tries each difficulty and keeps the set whose passage reads closest to the child's level (`generateFor` in `plans.ts`). The Daily Challenge (shared seed), Speed Run and Challenge do not adapt. The parent Reports page shows the estimate as one quiet line. Flag `reading-level-match` turns the matching off.
- Known limit: matching only chooses between the passages a unit already has per difficulty; a unit whose passages don't vary with difficulty can't adapt until more passages are written.

### Story Library
- **Short, original read-along stories** (`src/content/stories/`, flag `story-library`): 30 stories, six in each of five tiers (Kindergarten and Grade 1, Grades 2 and 3, 4 and 5, 6 and 7, 8 and 9), each 5 to 8 pages with a picture, and 2 (little kids) or 3 questions about what happened. The library is its own download (`loadStories`), cached by the service worker once loaded.
- **Levels are computed, not tagged:** each story's level is `textReadingLevel` of its text, and `stories.test.ts` keeps it inside its tier's range (`TIER_LEVELS`). The library puts stories on three shelves (Just right, A little easier, A bit of a stretch; `shelves` in `src/lib/stories.ts`) around the child's reading-level estimate, or their grade until the estimate exists (the `reading-level-match` flag switches the estimate off here too).
- **Read-along:** "Read to me" (on by default when `autoRead` is) reads each page with Piper or the device voice, lighting up the sentence being read (`speakSegments` with `onStart`/`onDone`); tapping a sentence reads it. Stories are written in Canadian spelling and shown to US children through `localizeStory`, and name nothing Canadian.
- **Questions follow the usual feedback rules:** a miss gets a hint quoting the page, a second miss shows the answer, and only first tries count. A finished story logs one `story` event (`rl`, first-try `results`, `pages`, `ms`). The first read of a story adds its answers to the reading samples, so stories feed the estimate; it earns 15 XP and 5 coins, plus 10 XP and 1 coin per first-try right answer on a first read. Learning time is capped at a minute per page and question.
- **Shown** as a Stories tile on the home screen (a Lessons-screen card for little kids) when language is on; the first 2 stories of each tier are free after the trial. Trophies (category "Stories"), a daily and a weekly quest, and a "Story time" sticker. No French stories yet.

### Lessons ("how it works")
- A unit can carry an optional `lesson` (2 to 4 short steps and one worked example; `Lesson` in `src/content/types.ts`). Lessons are written once per grade in `src/content/lessons/<grade>.ts`, keyed `subject/unit-id`, and attached by `withLessons` in each BC grade's `index.ts`, so a unit shared by BC, Ontario and Alberta has the lesson in all and each grade's lessons stay in that grade's download.
- Children open one from the unit dialog ("How it works") or, for little kids, automatically before their first practice of a unit. It never changes scoring. The public unit page shows it under "How we explain it".
- **Coverage today:** every unit in every subject and framework, Kindergarten to Grade 9 (`lessons.test.ts` enforces it). Math lessons are in `src/content/lessons/<grade>.ts`; the other subjects have their own file beside it (`g4-science.ts`, `g4-social.ts`, `g4-language.ts`, `g4-immersion.ts`, `g4-core-french.ts`), merged in `g4-subjects.ts`. That merge is a second download per grade (`moreLessons`), fetched once the grade is in and never waited for (`loadMoreLessons` in `src/content/index.ts`), so a grade's first download stays the size it was; until it arrives a unit just has no "How it works" button. Each grade's `grades/<g>/index.ts` exports its `lessons`, and `src/content/index.ts` (apps) and `all.ts` (tests) apply them to every framework's units with the same id, so units that only one province has still get the lesson without each province's grade file repeating them. Add a lesson when you add a unit. A lesson for a unit a US state uses must name nothing Canadian (unless the unit is that state's own), and French lessons mark French in « » so it is read in a French voice.

### Help videos

A watch is a `video` event (not practice); the parent Overview shows videos watched and how the next answer on that unit went (`videoStats`). ### Finish your lesson
- **A lesson left partway can be finished later** (`src/lib/resume.ts`, `ResumeCard.tsx`, flag `resume-lesson`): Practice, Review, the Daily Challenge and Math Facts keep their place on the device after each answer (`grademap.resume.<profile>` in `localStorage`: the lesson, its first-try results so far, its length and time spent; never synced, since every answer is already an event). For 48 hours (the Daily Challenge only that day) the home screen shows "Finish your lesson?" under the big button, for little kids in place of their one suggestion card; it opens the session with `resume=1`, which starts at the next question with the earlier answers counted in the session's total and the summary. Finishing the lesson, tapping Stop or "Not now" forgets it. Adventure (endless), Speed Run and Challenge (timed) are never kept. A unit that can't be opened any more (subject off, plan ended) shows no card.

### Feedback
- **A wrong answer gets a hint and another try.** A second miss shows the answer with an explanation.
- **Only first-try answers count** toward accuracy, stars and proficiency. Stars never go down.
- **A hint opened before answering counts like a retry** (`hinted` on the answer event): no first-try credit, 4 XP instead of 10, and it isn't a "comeback". A parent can turn on "Hints count as first try" per child (`freeHints`) so asking for help never lowers accuracy. Reports show how many hints were opened. The hint button appears only in modes with retries (not Speed Run or Challenge).
- **The tone is soft:** a gentle "try again" sound, not a buzzer, and encouraging messages. Never shame a child.

### Timers and the learn-to-play loop
- **Daily goal timer:** 10 minutes for little kids, 15 for everyone else. A child can tap the minutes on the home screen to pick Easy (about two thirds), Regular (the parent's goal) or Stretch (a third more) for the day (`src/lib/goal.ts`, a `goal` event). Finishing a Stretch goal earns +15 coins once a day. Parents can turn the choice off in Settings > Advanced options. Parents pick one "Timers in lessons" setting in Settings > Calm and focus (`src/lib/timers.ts`): Show all (an elapsed clock, plus countdowns in timed modes), Countdowns only (the little-kid default) or Hide all (a quiet bar in timed modes). It is stored in the older `showTimer` and `hideTimers` fields, with `hideTimers` winning, so saved choices and older devices keep working.
- **Learning earns arcade time,** Pomodoro-style. The default is 20 minutes of learning for 5 minutes of games, with a cap of 20 game minutes a day.
  - Parents can change all of these, turn games off, or allow free play (`src/lib/gametime.ts`).
- **Learning time is counted per answer, capped at 60 seconds,** so leaving the app open doesn't earn time.

### Gamification
- **The aim is the pull of a AAA game, pointed at report-card skills.**
- **XP:**
  - A correct first try earns 10, plus 2 per streak step (up to +10).
  - A fix after a miss earns 4; a revealed answer earns 1.
  - Session bonuses: +15 per session, +25 when perfect, +40 for the Daily Challenge, +30 for passing a Challenge.
  - Level *n* needs `80 + 40(n−1)` XP.
- **Coins** come from correct answers, sessions, games, trophies and quests. They're spent in a pretend shop on critter companions, titles and confetti styles.
- **Trophies:** 234 in the list, about 119 visible to a child at any one grade (mastery trophies are per grade), including French and Spanish groups kept in their own lists (`src/lib/trophies.ts`), in Xbox/PlayStation-style tiers. Everything a child can do has a trophy: every subject (a practice ladder for each of math, language, science, social studies, both French subjects and Spanish), every mode, the Story Library, every arcade game, streaks, levels, shop, and mastery for every grade and subject.

  | Tier | Points | Coins |
  | --- | --- | --- |
  | Bronze | 15 | 10 |
  | Silver | 30 | 25 |
  | Gold | 90 | 60 |
  | Platinum (one per grade: "Grade Champion"; plus 365 days practised, a 365-day streak, level 100) | 300 | 250 |

  - A few trophies are secret, including "Old School" (Konami code: arrow keys then B, A; on touch, eight swipes then two taps; `src/lib/konami.ts`).
  - Trophies pop up as **console-style toasts** that never take taps. A toast must never block the buttons underneath it.
- **Mastery trophies are per grade** (`grade-champion-4`, `master-math-4`, ...): only the child's current grade is shown and earned, so moving up gives new long goals. A trophy's optional `applies` hides it when the child's grade and curriculum have no such course (for example Core French before Grade 5 in BC), so nothing unearnable is shown. Trophies are not province-specific: they read the child's own `framework`, so a new framework needs no new trophies. When you add a subject, mode or game, add its trophy and quest in the same change. Old un-suffixed ids still count for points. Growth trophies (Emerging to Proficient, still Proficient after 30+ days away) and "days practised" (Journey) trophies are read from unit stats and day counts, never from loaded content.
- **Daily quests:** 3 per day from a pool of about 30, seeded and claimed automatically. Little kids never get Speed Run or Review quests.
- **Weekly quests:** 2 per week (Monday to Sunday), bigger rewards, also claimed automatically (stored as quest events keyed by the Monday's date, ids start `w-`).
- **Streaks:** a day counts if the child finishes a session, reads a story to the end or gives at least 5 answers. Every 7 practice days earns a rest-day shield (up to 2) that covers a missed day, so one slip doesn't erase a long streak. Shields are computed in `derive`, never stored.
- **Celebrations** (shop items with `kind: "confetti"`, `src/lib/shop.ts`): each has emoji pieces and a `pattern` for how they move (cannons from both sides, `fall` from the top, `float` up from the bottom, or `fireworks`), played by `celebrate` in `src/lib/juice.ts` at the end of a lesson, an arcade best and a purchase. A child can peek at one before buying, and switching to an owned one plays it. Bursts in one celebration are at least `MIN_BURST_GAP_MS` apart, so nothing flickers more than 3 times a second; reduced motion and calm mode stop them all.
- **Shop unlocks:** some items need a level or trophy as well as coins (`unlock` in `src/lib/shop.ts`).
- **Easter eggs** (`src/components/play/Secrets.tsx`, logged as `secret` events, shown as hidden trophies): Konami code (keys, or 8 swipes and 2 taps), tap your buddy 10 times, a polite moose that strolls past an idle home screen on about 1 day in 6, secret words typed on a keyboard, 11 right in a row, a lesson finished at 11:11. Never add anything that blocks taps or pushes late-night use.

### Parent-set goals, help and reading options

- **Scheduled assignments** (`class_assignments.starts_at`, `startsAt` on `/api/classes/assignments/`): a teacher can give a unit a start date (from today to a year ahead, never after its due date) to plan a week ahead. Until that day `familyClasswork` leaves it out of sync, so neither the child nor the parent sees it, and the class view treats it as nobody's yet (`assigned: false`, shown as "Starts Mon, Nov 3"), so insights, badges and the Monday email skip it. Homework on it counts from the start date, not from when it was planned.
- **Who an assignment is for** (`class_assignment_students`): a unit goes to the whole class unless the teacher picks students (`students` on `/api/classes/assignments/`; no rows means everyone). Only the picked students get it through sync, and the others show "Not assigned" and are left out of the class insights. The rows are deleted with the unit, the student, the link or the class; keep that complete when adding places that delete these.
- **Most-missed questions:** answer events now carry `q`, a short copy of the question's text (`questionLabel`, 80 characters, not set for questions with a picture), so the class view can list the questions at least 2 students missed on the first try, per assigned unit (`mostMissed`, `studentQuestions` in `src/lib/classroom.ts`; `missed` in the class response). It only covers answers given after this shipped. The text is the generated question (no child input), but it is now stored with practice results, so keep `/privacy/` and `docs/school/` true if that wording ever needs to say so.
- **Monday class email** (`src/lib/classDigest.ts`, `classDigests` in `src/server/dailyJob.ts`, `PATCH /api/classes/digest/`, flag `teacher-monday-email`): opt-in per teacher account (`parents.class_digest`, a checkbox on the class list; confirmed email only). On Monday (Tuesday finishes a Monday that ran out of time, `last_class_digest_at`), one email per teacher covering each class they own or co-teach with students and assignments: how many practised last week, current homework (due from a week ago on, or assigned in the last 4 weeks), units worth reteaching and students to check in with (`classInsights`). First names only, labelled as practice, with its own unsubscribe (`kind=class`). Keep `/privacy/` and `docs/school/` true if what it carries changes.
- **Class timer** (`class_timers`, `src/server/classTimer.ts`, `src/lib/classTimer.ts`; flag `class-timer`): a teacher or co-teacher starts a countdown (1 to 120 minutes, an optional note of up to 40 characters) from the Live tab; pause, resume, add a minute and stop. It shows on the teacher's screen and as a small pill at the top of every kids' screen (`ClassTimerChip` in `PlayApp`, which takes no taps and makes no sound) for children in a class, fetched with the live question in one poll (`GET /api/live/?profile=`, shared by both through `src/lib/livePoll.ts`; `?timer=1` still answers for older app versions) only while the device is online and visible. Devices work out the end time from `left` and when the answer arrived, so their clock doesn't matter. It is a plain countdown: it locks nothing and never touches practice, levels or reports, and it holds no child data. A finished timer says "Time's up!" for 5 minutes, a paused one goes after 3 hours, and it is deleted with the class's live questions (`liveClassStatements`).
- **Class goal** (`class_goals`, `src/server/classGoal.ts`, `src/lib/classGoal.ts`, `/api/classes/goal/`; flag `class-goal`): a teacher or co-teacher sets a weekly question target for the whole class (Progress tab); the server counts the members' `answer` events since the teacher's Monday (their time zone offset is stored with the target) each time it is asked, so nothing about a child is stored. Children in the class see one shared bar on the home screen (`ClassGoalCard`, not for little kids), counts only: no names, no ranking. It rides the device's live poll (`goal` beside `live` and `timer`), so it shows online only. The row is deleted with the class's live questions (`liveClassStatements`). It is the class counterpart of the family "Together this week" goal.
- **Live questions** (`src/server/live.ts`, `/api/classes/live/` for teachers, `/api/live/` for children's devices; flag `live-questions`): the teacher picks a unit and the server asks one multiple-choice question from its generator (seeded by class and number; units with no tap-to-answer questions are refused). Children's devices in a class poll for the open question only while online and visible (`useLiveQuestion` in `LiveQuestion.tsx`: every 3 s while one is open, 12 s otherwise; never for a child in no class) and show it at the top of the home screen; offline they show a calm note and practice carries on. The teacher sees a private preview of the next question while the current one is open (`previewNext`, kept on the row by `cachedPreview` so polling doesn't regenerate it; only on `/api/classes/live/`, never sent to children) and can swap it for a different one (`swapNextLive`, `next_swaps`); "Next question" asks the question that was shown. One answer per child counts; showing the answer closes the question. Live answers are stored apart from events, never change levels, XP or reports, and are deleted after a day (`pruneLive`, on each new question and in the daily job) and with the student, class or family. A teacher can look back at the last day's questions (`?recap=1`: how many answered right and who to check in with) and copy the recap as text before it is deleted; nothing is kept longer. Real time is polling, not WebSockets, because the functions run on Vercel.
- **Exit ticket** (`src/lib/exitTicket.ts`, in `LiveClass.tsx`; built on live questions, so same flag, no new table and the same one-day retention): the teacher picks 3, 4 or 5 questions and "Start an exit ticket" asks them back to back from the unit they chose ("Next question" each time, "Finish the exit ticket" on the last, which shows no preview). One results page then shows each question's right and answered counts, each student's score, who to check in with (answered but under 60% of the ticket) and who answered none, with "Copy the results" as text that says it is practice, not a report-card mark. The ticket's state (its size and the ids of the questions asked) lives only in the teacher's `sessionStorage` (`grademap.ticket.<classId>`), so a reload keeps it; ending it early shows the results of what was asked. Children's devices see ordinary live questions and nothing tells them it is a ticket. `previewNext` skips prompts already asked from the same unit in the last day, so a ticket never repeats a question.
- **Printing** (`TeacherApp.tsx`): login cards have a "Larger print (fewer cards per page)" option (one card per row, bigger name, codes and QR). The class summary prints sideways when it has more than `WIDE_SUMMARY_UNITS` (4) assigned units, through a CSS named page (`@page summary-wide`, `.print-landscape` in `globals.css`), not a runtime `<style>`, which the CSP forbids; a browser without named-page support prints it upright. `e2e-classroom.mjs` reads the page sizes from a real PDF.
- **School approval papers** live in `docs/school/` (PIA pack, data agreement, letter home, accessibility conformance). They are drafts for the owner; facts in them must stay true to the code, so update them when student data, providers or retention change. The public `/accessibility/` page and the "Schools and classes" section of `/privacy/` say the same things.

## Design decisions

### Look and feel
- **Kid-friendly but not noisy:** lots of colour without distraction, large touch targets, and tablet-first layouts that also work on phones.
  - There must be no horizontal scroll from 320 px wide.
  - The main button on each screen (Let's go, Adventure / Let's Play) must be visible without scrolling.
- **Small screens:**
  - Two Tailwind variants in `globals.css` handle the tightest screens.
    - `short:` is for phones held sideways (height 500 px or less).
    - `narrow:` is for 320 px phones.
    - Use them to drop decoration (extra mascots, the greeting critter) before shrinking anything a child taps.
  - Game boards shrink to fit short screens; the games measure their board size.
  - Every screen change scrolls to the top (`src/lib/router.ts`).
- **Fonts:** Fredoka for headings and buttons; Andika, designed for beginning readers, for questions and stories.
  - Theme tokens and animations live in `src/app/globals.css`.
- **Subject colours:** math blue `#4f8ef7`, language pink `#e9559a`, science green `#25b47e`, social orange `#ff9636`.
  - Use them for subject identity in the kids' UI only, never in charts.
  - **Text on these bright fills is very dark navy (`#0f172a`), not white,** because white fails the WCAG AA contrast rules (see `src/lib/contrast.ts`, `onColour`). The arcade purple is `#7c4fe0` for the same reason. Don't put white text on a bright fill; `node scripts/e2e-a11y.mjs` will catch it.
- **Mascots:** an original cast drawn from one parametric SVG (`src/components/Critter.tsx`). Every critter shares the same moods, and their eyes follow the pointer.
  - Ollie the Otter is the guide.
  - Each subject has its own guide: Hoot the owl (math), Ruby the fox (reading), Bolt the beaver (science) and Juniper the bear (social studies).
  - Twenty-five more critters can be bought in the shop (ten of them also picked as avatars; the fifteen marked `shopOnly` are shop-only buddies, some locked behind a level or trophy).
- **Read-aloud uses the device's own voices** (Web Speech API, `src/lib/speech.ts`) until the Piper voice below has downloaded, and whenever Piper can't play, so it's free and works offline.
  - Installed voices are ranked by quality, and locale only breaks ties between similar voices:
    - first, "Natural", "Neural" and "Premium" voices;
    - then "Enhanced" and Google voices;
    - then standard voices;
    - last, old Windows desktop voices and Apple's Eloquence voices.
  - Apple's novelty voices are never offered.
  - Cloud voices (Edge's Natural voices, Google voices) are skipped when offline, with a retry on an on-device voice if one fails.
  - Parents can pick a voice with a preview under Account (this device). The choice is saved per device in `localStorage`, not synced, because every device has different voices.
 - Pitch stays at 1; raising it makes good voices sound processed.
- **Piper voice, on by default** (`src/lib/piper.ts`, `public/piper-worker.js`): a neural voice from rhasspy/piper-voices (Amy, `en_US-amy-medium`, for English; Siwis, `fr_FR-siwis-medium`, for French; Ald, `es_MX-ald-medium`, for Spanish; listed in `src/lib/piper-manifest.json` with file hashes). It runs on the device in a web worker (eSpeak NG turns text into phonemes with `piper_phonemize.wasm`, then onnxruntime-web runs the voice), so it costs nothing to run and works offline once downloaded. Piper was replaced by Kokoro and then Supertonic in October 2026, and brought back on October 25 because the owner judged both worse than Amy (owner's decision: don't switch away from Piper without asking). `piperText` puts maths symbols into words first, because eSpeak reads many of them oddly.
 - The voices download in the background when `/play/` or `/parents/` opens (`VoicePreload`, `preloadPiperVoices`, after the lessons have loaded), but only when a child on the device has "Read questions out loud" on (`autoRead`: Kindergarten and Grade 1 by default, or a parent turned it on); English, plus French when such a child also has a French subject. Tapping 🔊 (in any grade) also starts the download for that language. The device voice reads until the voice is here, and Piper from then on. No background download on mobile data, Data Saver or a 2G connection (where the browser reports it; Safari doesn't), when the device has little space, offline, or in automated browsers (`navigator.webdriver`, so e2e runs don't each fetch about 100 MB). A failed background download shows no error and is retried after 10 minutes. The `piper-auto-download` feature flag turns background downloads off.
 - A parent's choice wins: the switch under Account is saved per device in `localStorage` (`grademap.piper` = `on`/`off`). With no saved choice it's on; picking an English device voice turns Piper off, and removing the English voice turns it off too. Downloading by hand turns it on. The files live in their own Cache Storage (`grademap-piper`), so a parent can remove them.
 - **One-time reset when Piper came back** (`resetOldVoiceChoices` in `piper.ts`): every device clears its earlier voice choices once (`grademap.piper`, `grademap.supertonic`, `grademap.kokoro`, and the picked device voices `grademap.voice` and `grademap.voice.fr`), then records `grademap.voiceReset` = `piper-amy-1`, so Piper reads everywhere and choices made afterwards stick. The `grademap-kokoro` and `grademap-supertonic` caches are deleted. To force another reset, bump `RESET_VERSION`.
 - Pauses in read-aloud (between a question and its answers, and between answers) are halved when Piper reads (`PIPER_PAUSE_SCALE`), because each Piper piece already takes a moment to make.
 - If Piper fails (an error, or no sound within 15 s), the device voice reads that question and every later one in that language until the page reloads. A device-voice preview under Account always uses the device voice.
 - Speed: device voices read a touch slow (0.92), but Amy is unhurried already, so she reads at 1.15 (`PIPER_RATE` in `src/lib/speech.ts`). Siwis keeps 0.92.
 - We host every file ourselves. The site serves them from `/piper/{version}/` (version 3; the voices are unchanged since version 2). The engine (onnxruntime-web and `@diffusionstudio/piper-wasm`) is copied from `node_modules`; the voices come from our GitHub release `piper-voices-2` (`voiceSource` in the manifest, copied unchanged from rhasspy/piper-voices). `scripts/fetch-piper.mjs` downloads them, checks the sha256 and puts them in `public/piper/` (gitignored) on `prebuild` and, optionally, on `dev`. Don't commit the voice files to git or Git LFS (about 127 MB).
 - Never replace or delete a release's assets. To change a voice, upload a new `piper-voices-{n}` release, update the manifest's hashes and `voiceSource`, and bump `version`.
 - Show each voice's credit line (Amy: Mycroft Mimic3 voices dataset; Siwis: SIWIS database, CC BY 4.0; Ald: Ald Mexican Spanish dataset, public domain) and the Piper and eSpeak NG (GPL-3.0) credit.
 - A cloud neural voice (Azure, Google or OpenAI, with a shared audio cache) is the option if device voices aren't good enough. It's not built; ask the owner before adding one, because it has a running cost.
- **Keyboard and high contrast** (WCAG 2.1.1, 2.4.1, 2.4.7):
  - Every page with a header starts with a "Skip to main content" link (`src/components/SkipLink.tsx`); each `<main>` carries `id={MAIN_ID}` and `tabIndex={-1}`. The link moves focus without touching the URL, because the apps use hash routes.
  - In questions, number keys pick a choice (1 is the first; `aria-keyshortcuts`), and Enter presses Check unless focus is on another button (`src/lib/keys.ts`). The keypad and PIN also take typed digits. No visible key hints, to keep the kids' screen calm.
  - Never remove the focus ring (`outline-none`) without a replacement ring.
  - Windows high contrast (`forced-colors`) drops fills, so anything shown only by colour needs a border or system colour in the `@media (forced-colors: active)` block in `globals.css`: a picked option (`aria-pressed`, `aria-current`, `aria-checked`), right and wrong answers (`data-state`), switches (`switch-track`, `switch-knob`) and progress bars and sliders (`progress-track`, `progress-fill`). Mark the active item in a nav with `aria-current="page"`.
- **"Juice it or lose it":**
  - Squash-and-stretch buttons and synthesized sounds with slight pitch variation (no audio files).
  - Bursts, floating "+XP" text, screen thumps and confetti.
  - **All motion must respect `prefers-reduced-motion`.**

## Architecture decisions

- **Offline-first.**
  - Everything a child does is appended as an event with a unique id. Events go to IndexedDB first (`src/lib/localdb.ts`).
  - XP, levels, coins, trophies, mastery and streaks are **never stored**. They're recomputed from events (`src/lib/derive.ts`), so merging devices is order-independent and duplicate-safe.
  - Profiles, settings and the family record use last-write-wins on `updatedAt`.
- **Sync** (`src/lib/sync.ts` → `POST /api/sync/`):
  - pushes unsynced events and pulls new ones by cursor;
  - runs when the device comes online, when the app becomes visible, every 2 minutes, and a few seconds after any change.
- **Service worker** (`public/sw.js`):
  - precaches `/play/` and `/parents/` along with their build files;
  - keeps grade files loaded on demand: the app posts the files it has loaded (`cache-urls`), including those fetched before the worker took control on a first visit;
  - serves pages network-first and hashed build files cache-first;
  - never caches `/api/` or client-navigation data.
- **Each grade's lessons are a separate download.** The client content store `src/content/index.ts` loads a grade with `loadGrade` (a dynamic `import()` from each framework's manifest).
  - The kids' app waits for the active child's grade, and the parent area for its children's grades (`ContentGate`, `useGradeContent`).
  - After that, the other profiles' grades and the grades either side are prefetched when the browser is idle, so switching players or moving up a grade works offline.
  - If a grade was never downloaded and the device is offline, kids see a friendly "connect once" screen with Try again.
  - First load of `/play/` is about 230 KB of gzipped JS plus 17–100 KB for one grade. Before this split, it was 775 KB for everything.
  - **Occasional kids' screens are their own downloads too** (`src/components/play/lazyScreens.tsx`: arcade and games, shop, room, stories, trophies, stickers, trail map, placement, math facts, treasures, sneak peek). `prefetchScreens` fetches them all when the browser is idle once the app is up and hands them to the service worker, so they open offline; `e2e-offline.mjs` checks a few. A screen still downloading shows `ScreenLoading`, and a failed download offers Try again. Keep the home screen, a lesson and a session in the main bundle, and add a new occasional screen to `lazyScreens.tsx`. First load of `/play/` is about 330 KB of gzipped JS (October 2026, not counting the `noModule` polyfills modern browsers skip).
  - **Never import `src/content/all.ts` (every grade) from client code.** It's for statically generated pages and tests, and ESLint blocks it elsewhere. It and `GUIDES` (`src/content/guides.ts`) load every framework through the registry with a top-level `await`, so they are server-only.
  - **Scoring must not depend on which grades have loaded.** Code that runs over events (`derive`, reports) reads the subject from the unit key (`parseUnitKey`) instead of looking up content.
  - Trophies that count "every unit in your grade" use a target of at least 1, so an unloaded grade can never award them.
- **Country facts live in one module** (`src/lib/country.ts`): locale, currency, number grouping, the region word, the grade range and whether parental consent applies. Read them with `countryOf(framework or family)` instead of testing `country === "US"`; parse stored codes with `toCountryCode` (empty means Canada, unknown throws). Data that differs by country (game rounds, capitals, history) is a `Record<CountryCode, …>`, so adding a country is a type error until every record has it. Public page copy that differs by country still checks the code where it is written.
- **The kids' app and parent area are single-page apps with hash routes** (`src/lib/router.ts`), so every screen works offline from one cached page.
- **Every tap gets an answer within a frame or two** (October 2026, Melvin: some clicks took a long time before anything happened):
  - The kids' app and parent area switch screens with `useShownHash` (`src/lib/router.ts`). A screen that drew in under `SLOW_DRAW_MS` last time (this page load) is drawn straight away; one that was slow or is new first shows a `RouteProgress` bar over the old screen and is drawn once that has been painted (`afterPaint`). Drawing in the background with `useDeferredValue` was tried and made screens finish 100–300 ms later on a slow tablet, so don't switch to it. The screen switcher must be a `memo` component that takes the hash string, or the old screen is drawn again first, and sit inside `<ShownRoute value={shown}>`, so `useRoute` in a screen still on show reads its own address and doesn't act on the next one (a "Play free" link once went home instead of to its unit that way). The parent tab lights up at once.
  - Links from public pages into an app are `AppLink` (`src/components/site/AppLink.tsx`): never prefetched (the apps are big), with a spinner while the tapped app downloads. Use it for any new "Play free", "Try it free" or sign-in link.
  - Session logs answers with `logSoon` (`src/lib/store.ts`), after the paint, because re-deriving a child's stats grows with their history; the next `log` (or switching players, or leaving the page) logs anything queued first, so order is kept.
  - `node scripts/bench-clicks.mjs <base> [runs]` times taps on a slowed tablet with a year of practice seeded (see the Commands list).
- **Server:** libsql, a local SQLite file in dev and Turso in production.
  - Auth hashes passwords with scrypt. Sessions are random tokens stored hashed, in an HttpOnly cookie, with a same-origin check.
- **Cloudflare is DNS only** (grey cloud on `gradelings.com` and `www`, October 2026). Vercel is the only CDN; don't turn Cloudflare's proxy, caching or HTML rewriting (Rocket Loader, email obfuscation) back on: they add a hop and break the hashed CSP.
- **`trailingSlash: true` means every API URL ends in `/`.** Call `/api/sync/`, not `/api/sync`. Stripe's webhook endpoint must be `/api/billing/webhook/`, because Stripe doesn't follow redirects.
- **Content Security Policy has no `'unsafe-inline'` in production, and pages stay static** (`src/lib/csp.mjs`). Nonces would need dynamic rendering for every page, and Next's experimental SRI doesn't cover inline scripts.
  - `npm run build` is `next build && node scripts/csp-postbuild.mjs`. The script hashes every inline script, `<style>` and `style=""` value in each prerendered page and writes that page's policy into a `<meta http-equiv>` tag right after the charset. Run `next build` alone and the pages have no script policy, so don't change the `build` script. On Vercel, which builds through its own Next.js adapter (`NEXT_ADAPTER_PATH`) and copies pages out during `next build`, `next.config.ts` wraps that adapter with `scripts/csp-adapter.mjs`, which writes the same tags first; both share `scripts/csp-pages.mjs`.
  - The header from `next.config.ts` carries only what a `<meta>` tag can't set (`frame-ancestors`, plus `base-uri`, `form-action` and `object-src`). It must **not** gain `default-src`, `script-src` or `style-src`: browsers combine the header and the tag, so those would block the hashed scripts.
  - `/shared/{token}/` and the shared milestone pages under `/milestone/` are rendered on every request, so `src/proxy.ts` gives them a per-request nonce instead. That policy allows no `style=""` attributes, so those pages are built from classes only. `next dev` uses a permissive policy because hot reloading needs it.
  - Inline `style` props set from client code are fine (they go through the CSSOM). `setAttribute("style", …)` and `<style>` elements added at runtime are blocked.
  - Playwright's playthrough fails on any console error, which includes CSP violations, so a regression shows up in CI.
- **Sentry** (`src/instrumentation.ts`, `next.config.ts`, `docs/DEPLOY.md` section 5): the server sends errors and a sample of timed API requests (`src/lib/sentry-traces.ts`; `SENTRY_TRACES_SCALE=0` turns timing off); the browser sends errors only and loads the SDK when something goes wrong. Everything goes through `src/lib/sentry-scrub.ts`. With `SENTRY_AUTH_TOKEN`, `SENTRY_ORG` and `SENTRY_PROJECT` set at build time, the build uploads source maps and deletes them; without them `next.config.ts` is unchanged. Keep `/privacy/` and `docs/school/` true if what is sent changes.
- **Public pages must stay light.** They must not import the store or the content bundle on the client.
  - For example, `sound.ts` gets the "sound on?" check injected by the store instead of importing it.
  - Check the size of the JavaScript a public page loads after changing shared client modules.
- **Public pages are statically generated** with `dynamicParams = false`.
  - Sample questions are seeded from the unit key, so pages are identical on every build.
  - `/play/`, `/parents/` and `/api/` are `noindex` and disallowed in `robots.ts`.
  - **Vercel's deploy takes a limited number of prerendered outputs** (each page is its HTML, its `.rsc` and three segment prefetch files). Above about 165,000 its "Deploying outputs" step fails with "Maximum call stack size exceeded" (October 2026, after Mississippi and Kansas). `scripts/deploy-outputs.mjs`, run by the CSP adapter on Vercel, leaves out unit pages' segment files (Vercel serves the page's `.rsc` for them) and stops the build above `PRERENDER_BUDGET` with a clear message. The adapter logs the count after each Vercel build ("prerendered outputs remain"); a new state adds about 2,000. If the budget is reached, trim more segment files or render a page kind on demand, never drop pages from a framework.

## Content rules

- **Research sources are committed, in their own repository** (owner, October 2026): every framework's folder in [gradelings-research](https://github.com/mjparinas/gradelings-research) (moved out of `docs/research/` on October 31) keeps the official documents it was built from in `source/` (with `.txt` extracts of PDFs), a `fetch.sh` that downloads them again, a `build_outcomes.py` that rebuilds `outcomes.json` from `source/` exactly, and a README with URLs and dates (`docs/ADDING_A_PROVINCE.md`, step 2). Commit the sources even when the site allows downloads; when you refresh a framework, re-run `fetch.sh` and commit the new files with the rebuilt JSON there. Only the built JSON the tests read stays here in `docs/research/<folder>/`, at the same paths, and must match the research repository's copy (`docs/research/README.md`).

- **Curriculum locks** (`src/content/locks/`, checked by `src/content/lock.test.ts`): each framework's lock lists its courses, units in order, and a hash of each unit's text, standard and questions at fixed seeds; `sizes/<id>.json` records each grade's download for that framework (gzipped source reached from the grade files the apps load). Units are shared, so a change to one unit can reach many frameworks: after an intended change, run `npm run curriculum:lock` and commit the locks (with `dates/<id>.json`, the day each unit, course and set of guides last changed, which moves only for what changed), and check the diff names only the frameworks you meant to change. A download that grows more than 10% fails until it is re-recorded; check nothing extra is imported first. Every lock, dates and sizes file is one per framework, so a new state adds files and edits none; on a merge conflict in one, take either side and re-run the command.

- **Placing units in a framework** (`src/content/placement.ts`): every framework shares BC units, adopts copies of other frameworks' units and adds its own through the same helpers (`planGrade` for plan-driven frameworks, `courseOf` and `adoptUnits` for hand-built courses, `followBcGrade` for Yukon and the NWT). Each framework's `kit.ts` only names its id, citation style and plan. Fix placement behaviour there, not in a kit.

Full guide: `docs/CONTENT_GUIDE.md`. The essentials:

- **Generation:**
  - Every unit has `generate({ difficulty })` that returns 6–10 questions (8 by convention) at difficulty 1, 2 or 3.
  - **Every course has enough to practise:** each framework's grade and subject needs at least 5 units and 250 distinct questions (French: 5 units and 120). `src/content/depth.test.ts` counts them and lists the few known exceptions.
  - **Never use `Math.random` in content.** Use the seeded helpers in `src/content/random.ts`.
- **Questions must be fair:**
  - the answer is among the choices;
  - no two choices look alike;
  - no wrong answer that is also defensibly right;
  - the maths checks out.
  - `src/content/content.test.ts` enforces this. Keep it passing and extend it rather than weaken it.
- **Little kids:**
  - Pre-K questions are picture-only, with at most 3 choices (see Pre-K above).
  - Prompts are at most 80 characters, with at most 4 choices (5 for older kids).
  - No typed answers in Kindergarten.
  - Use `speak` when read-aloud should differ from the text, and `speak: ""` to stay silent.
- **Typed answers:**
  - Answers fit the 9-character keypad.
  - The decimal and fraction keypads have no minus key, so negative answers use the integer keypad.
- **Canada:**
  - Canadian spelling (colour, centre, practise as a verb).
  - Money in multiples of 5¢, since there are no pennies.
  - Big numbers with Canadian spacing (`345 678`), plus a `speak` version for read-aloud.
- **People and sources:**
  - Diverse, region-neutral names, and no brand names.
  - Original passages only.
- **Indigenous content:**
  - present tense, living communities;
  - never treat all Nations as one ("some", "many");
  - no sacred or ceremonial details and no stereotyped emoji;
